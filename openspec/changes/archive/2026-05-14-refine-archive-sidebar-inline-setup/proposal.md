# v0.2.7 可折叠写作存档栏与编辑器内设置修改

## 背景

v0.2.6 已经建立了写作存档、主写作界面和显式大纲检查，但新的交互仍有两个问题：

- 写作存档侧栏更像普通管理面板，还缺少 ChatGPT 式的可折叠导航、当前项高亮和条目菜单。
- 主题/大纲修改通过 Writing Setup 抽屉完成，动作偏重，容易把用户从正文写作状态拉走。

用户希望参考 ChatGPT 侧边栏逻辑：写作存档可以折叠，每条存档通过三个点展开操作，并支持删除。同时，删除“修改主题/修改大纲”的展开抽屉，把修改能力嵌入编辑器内部，入口轻量但可发现。

## 改动范围

- 将写作存档侧栏改为可折叠栏。
- 折叠状态只保留必要入口，例如展开、创建新写作和当前存档提示。
- 每条写作存档提供 `...` 操作菜单。
- 存档菜单至少支持重命名和删除。
- 删除存档必须有确认步骤，避免误删本地正文。
- 删除当前存档后：
  - 若仍有其他存档，切换到最近打开或列表中合理的下一个存档。
  - 若没有其他存档，创建一个空白本地存档并保持在编辑器中。
- 移除主界面 Writing Setup 抽屉交互。
- 将文章主题、写作领域和大纲点的修改能力嵌入编辑器区域。
- 编辑器内修改入口保持低调，避免抢正文焦点。
- 主题或大纲在编辑中不调用 `/api/check-outline`；用户确认保存后才调用。
- 保持首次无本地写作时独立 Writing Setup 入口不变。

## 非目标

- 不引入登录、数据库、云同步或服务端持久化。
- 不引入写作存档版本历史、导入导出或复杂批量管理。
- 不把 LinguaType 改成聊天消息流。
- 不改变 latest-sentence enhancement、Apply/Cancel、range replacement、conflict detection 或 background learning extraction。
- 不自动生成正文、自动续写、自动决定观点或自动改写段落。
- 不扩展 Selection Actions 的能力范围。

## 预期结果

主界面更接近现代 AI 写作产品的工作台结构，但仍保持 editor-first：

```text
可折叠写作存档栏
  -> 新建写作
  -> 存档列表
  -> 每条存档 ... 菜单：重命名 / 删除

中央正文编辑器
  -> 文章主题以轻量文本展示，可原地编辑
  -> 写作领域可原地编辑
  -> 段落标题显示大纲点，可轻量原地编辑
  -> 确认保存主题/大纲后再检查大纲

右侧低频工具区
  -> Learning Library、Writing Habits、Tools / Settings、Data Control
```

用户可以像管理 ChatGPT 对话一样管理本地写作稿件，但稿件仍是本地文章草稿，不是对话，也不触发学习数据保存。

## 风险

- 删除存档是破坏性本地操作，必须有确认，并且不能误删 Learning Library、Correction Events 或旧 legacy key。
- 删除当前存档后的切换规则必须明确，避免出现 active archive 为空导致编辑器状态不一致。
- 将设置修改从抽屉改为编辑器内联，会影响 `LinguaTypeApp` 和 `WritingEditor` 的职责边界，需要避免把编辑器组件变成全局状态容器。
- 大纲内联编辑仍要保持“确认后检查”的规则，避免回退到输入中自动调用 LLM。
