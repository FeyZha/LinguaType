# 长文本中文占位建议流

## 背景

当前主写作区仍带有大纲驱动的分段结构：正文被拆成多个段落块，并显示 `第 1 段自由写作` 等标题。这个形态有助于按 outline 写作，但会打断用户在同一块长文本里连续表达的节奏。

新的目标是让 LinguaType 更像“输入法候选”而不是“改写工具”：用户可以自然写英文，卡住时直接把中文表达留在句子里。中文不是错误，而是表达占位符。系统先轻量识别，等句子边界稳定后再给一个当前句英文候选，并把中文表达如何转成英文表达单元讲清楚。

## 改动范围

- 主写作区去除大纲正文组织：
  - 不再按 `outlinePoints` 渲染多个正文块。
  - 不再在正文流中显示 `第 N 段自由写作` 或 outline heading。
  - 保留文章标题和写作领域作为低干扰上下文。
- 正文还原为一整块长文本 `contentEditable` 写作区域：
  - 底层仍保存为单个 `text` 字符串。
  - range replacement、autosave、Writing Archives、Selection Actions 继续基于该字符串。
- 新增中文占位识别：
  - 用户输入中文片段时，系统只做弱提示。
  - 中文片段不算校对错误，也不自动翻译。
- 新增句子稳定触发：
  - 当含中文的当前句遇到句号、问号、感叹号、换行、停顿 800ms 或 `Ctrl/Cmd + Enter` 后，才触发建议。
  - AI 只处理该当前句，不处理全文，不生成新论点。
- 当前句建议改为中文占位建议卡：
  - 显示自然英文句子。
  - 显示 `中文表达 -> 英文表达` 学习点。
  - 显示一个可复用结构。
  - 操作为采纳、忽略、换一种说法。
- 采纳后才替换当前句，并沉淀表达资产到本地 Learning Library。

## 保留约束

- 不自动替换正文。
- 不自动保存学习数据。
- 不重写整段或全文。
- 不做聊天窗口、右侧建议面板或弹窗。
- 不新增登录、数据库、云同步或 Chrome extension。
- 所有学习资产仍写入 localStorage。
- API key 与 provider 抽象规则保持不变。

## 非目标

- 不实现完整 Markdown 编辑器。
- 不实现多候选翻译列表。
- 不在用户仍在 composition 输入中文时调用 AI。
- 不移除 Writing Setup 的历史存储兼容能力。
- 不改 Learning Library 的管理页能力。

## 预期结果

用户看到的是一整块可连续输入的长文本写作区。输入中文时，只出现轻量提示；句子完成或停顿后，当前句下方出现一张紧凑内联建议卡。用户采纳后，该句被替换为自然英文，同时表达学习点进入表达库。整个体验保持写作流，不把 AI 变成打断器。
