# 设计说明

## 核心原则

本次变更把主写作体验从“按大纲分段写作”调整为“长文本连续写作 + 中文占位建议”。底层仍以单个 `text` 字符串作为业务真相，避免破坏现有 autosave、Writing Archives、range replacement 和学习数据流。

AI 介入的边界从“任何最新句都可增强”收窄为“当前句包含中文占位符时给建议”。纯英文句子不自动触发 AI；用户仍可以保留后续手动增强入口，但本次主交互聚焦中文占位表达。

## 写作区结构

`WritingEditor` 改为一个原生 `textarea` 长文本输入面：

- `value` 直接对应全文正文。
- 不再根据 `outlinePoints` 拆分正文块。
- 不再渲染 outline heading 或段落 heading。
- 文章标题仍由 `InlineSetupControls` 在正文上方展示和编辑。
- placeholder 继续提示可以直接夹中文。

正文 DOM 与业务 text 的同步规则：

- `onChange` 读取整个 textarea value，传给 `onChange(value)`。
- composition 中不触发建议生成。
- selection start/end 直接映射到全文 offset。
- `setCursor(offset)` 和 `getSelectionRange()` 面向全文 offset。

## 中文占位符识别

新增本地工具函数：

```ts
detectChinesePlaceholders(text): ChinesePlaceholder[]
findCurrentChinesePlaceholderSentence(text, cursorOffset): PlaceholderSentence | null
isSentenceBoundaryInput(value): boolean
```

识别规则：

- 中文字符范围作为占位符核心。
- 连续中文、中文间空格、常见中文标点可归为同一占位片段。
- 英文上下文不算错误。
- 无中文时不自动触发建议。

弱提示第一阶段只在 UI 中说明“已识别中文表达占位”，不显示大卡片，不调用 LLM。

## 触发策略

触发当前句建议的条件：

- 用户输入 `. ? ! 。？！` 或换行后，只把当前句标记为“可触发”。
- 当前句已完整并保持稳定 800ms 后，后台请求建议。
- 用户按 `Ctrl/Cmd + Enter`。

触发前必须满足：

- 当前句包含至少一个中文占位符。
- 当前句已经完整；只输入中文片段时只显示弱提示，不请求模型。
- 不在 IME composition 中。
- 当前没有相同 sentence range 的请求正在运行。
- 当前句内容与上次已忽略或已完成的相同请求不重复触发，除非用户手动再试。
- 自动后台请求期间不显示加载弹窗、加载条或文档流内状态块；底部状态栏位置不受请求影响。
- 文章标题与正文写作列使用同一列宽和左边界；正文输入面在浅色/深色主题下都保持透明、无卡片感。

## API 与模型结果

第一阶段复用 `/api/enhance-fast`，但请求只传入含中文占位符的当前句。后续可以再拆出更专门的 API，但本 change 优先减少 API 面扩张。

前端从返回结果中派生建议卡：

- 自然英文句子：`finalSentence`
- 中文表达：从当前句本地提取第一个或主要中文片段
- 英文表达：从 `finalSentence` 与中文片段位置附近的英文增量做保守提取；如果无法稳定提取，则使用完整 revised sentence 作为候选说明
- 可复用结构：优先使用模型 `explanationZh` 的短句；必要时前端截断为一行

模型不返回 diff，diff 仍由本地代码生成。

## 内联建议卡

自动生成建议后，编辑器先在问题句右侧空白区域显示一个低干扰小图标，不立即展开卡片，也不再用虚线、边框或整句下划线持续标记正文。图标通过隐形定位层跟随目标句首行，避免破坏原生 `textarea` 的点击、选区和光标体验。用户点击图标后，问题句临时成为焦点句，建议卡紧跟句子下方，其他内容顺势下排，作为正文流内的低干扰块。内容最多三层：

1. 自然英文句子。
2. `中文表达 -> 英文表达`。
3. 一个可复用结构。

卡片不重复显示完整原句；完整原句只作为焦点句出现一次。焦点句中的中文意群以下划线标记，点击或悬停意群后，高亮英文建议句和学习点中对应的英文表达。若用户写的是整句中文，学习点应收缩到真正卡住的表达单元，例如 `会火 -> go viral`，而不是重复整句。

操作：

- `Tab` 或采纳：替换 captured range。
- `Esc` 或忽略：关闭建议，不改正文。
- `Ctrl/Cmd + R` 或换一种说法：针对同一 captured range 重新请求。

采纳前仍做 `snapshotFullText` conflict detection。若正文已变，禁止自动应用，并提示重新生成。

采纳或忽略后，句子回到原本正文位置。已处理过的建议保留右侧复习入口，但不在正文上继续绘制虚线或框；用户再次点击该入口，可以重新打开同一条建议卡。

## 学习资产沉淀

采纳后立即完成正文替换，然后保存一个简短表达资产到 Learning Library：

- `content`: 英文表达单元。
- `chineseMeaning`: 中文占位片段。
- `usageNote`: 可复用结构。
- `sourceSentence`: 采纳后的英文句子。

仍使用既有 `upsertLearningItems` 去重规则，不新增云端存储。

## 测试策略

- 本地中文占位识别纯函数测试。
- `WritingEditor` 长文本输入、selection、快捷键测试。
- `LinguaTypeApp` 自动触发去抖、只处理含中文当前句、采纳后保存学习资产测试。
- 回归验证：无中文输入不自动调用 AI；忽略不保存；正文冲突时不应用。
- 视觉验证：本地浏览器输入完整句后，确认标题/正文对齐、状态栏固定底部、右侧图标与目标句对齐、正文没有虚线/边框干扰、卡片不重复完整原句。

## 追加稳定性约束

- 自动建议是后台异步任务：只要文本中存在已完成且含中文的句子，就可以为多句分别生成建议，但不得阻塞输入、不得显示加载卡片、不得影响底部状态栏。
- 手动快捷键处理光标所在句；自动扫描处理全文内含中文的完整句。两者都只请求单句，不改写整段或全文。
- 正文不再显示句下虚线或边框；右侧小图标通过隐形定位层与目标句首行对齐。
- 打开建议时，目标句临时独立成段并在其下方紧跟内联卡片；采纳或忽略后恢复原文档排布。
- 已调用过的建议即使在文本替换后仍保留复习入口，但新建或切换到其他档案时不得显示其他档案的旧卡片。
- 表达库页面进入动效与内容项动效使用同一套轻量上浮参数，避免页面头部和列表项出现两种视觉节奏。
