# v0.2.6 主界面壳层、写作存档与上下文设置优化

## 背景

v0.2.5 已经引入 Writing Setup、分段写作、大纲检查和 Theme Preference，但主界面仍有几个明显摩擦：

- 视觉和信息架构仍偏传统工具面板，和用户期待的 ChatGPT、豆包、千问式现代写作工作台有差距。
- 本地存储过主题后，用户无法在不离开写作上下文的情况下回到准备信息并修改主题或大纲。
- 目前只有单一 draft，不能像对话历史一样保存多次写作内容。
- 大纲检查会随 setup 状态变化自动触发，新增或编辑大纲时容易过早调用大模型。
- 大纲管理在主界面单独成块展示，与正文段落上已有的大纲标识重复。
- Selection Actions 浮层固定在编辑器左上角，可能挡住写作内容，也可能在第二段选中文本时显示到第一段区域。
- Selection Actions 标题存在中英文重复，解释结果展示不够结构化。

本 change 目标是在保持 LinguaType editor-first、localStorage-only 和 latest-sentence enhancement 核心契约不变的前提下，重塑主界面信息架构，加入本地写作存档，并把主题/大纲修改、大纲检查和选中文本操作改成更明确、更不打扰写作的交互。

## 改动范围

- 将主界面调整为更接近现代 AI 写作产品的工作台结构：写作存档列表、中央正文编辑器、低频工具区或设置抽屉。
- 新增 localStorage-only 写作存档，支持保存多篇写作内容、切换、重命名和新建。
- 将“退回准备页”改为抽屉式 Writing Setup：用户在主界面展开设置侧边栏修改主题、领域和大纲，不离开当前正文。
- 首次进入且没有 setup/archive 时仍可展示独立 Writing Setup；进入主界面后，后续修改使用抽屉。
- 将主界面独立“文章大纲”管理区移除，大纲只作为正文段落上方的标识和局部编辑入口出现。
- 大纲默认锁定不可编辑；用户点击“修改大纲”后进入编辑态。
- 只有点击“确定”保存大纲后，才调用 `POST /api/check-outline`。
- 大纲检查只检查主题与大纲一致性，非阻断展示问题建议，不自动改写大纲或正文。
- Selection Actions 浮层根据真实选区位置显示，优先出现在选区上方，避免遮挡选中文本和主要写作内容。
- Selection Actions 去掉重复英文标识，保留中文优先的用户界面。
- `/api/explain-selection` 的前端展示改为结构化解释，但仍不得返回或应用替换文本。

## 非目标

- 不把 LinguaType 改成聊天机器人或消息流产品。
- 不新增登录、数据库、云同步、支付或服务端持久化。
- 不自动生成文章正文、自动续写、自动决定用户观点或自动改写段落。
- 不改变 latest-sentence enhancement 的 Apply/Cancel、range replacement、conflict detection 或 background learning extraction 规则。
- 不把 Selection Actions 扩展成选中文本改写、润色或替换工具。
- 不新增导入功能或复杂版本历史；本 change 只做本地写作存档的最小可用集合。

## 预期结果

用户进入主界面后，核心体验变为：

```text
左侧写作存档
  -> 选择或新建一篇写作

中央正文编辑器
  -> 段落标题显示大纲点
  -> 最新句增强仍在正文附近完成 Apply/Cancel

设置抽屉
  -> 修改主题、领域、大纲
  -> 确定后保存并检查大纲
```

用户可以像管理对话一样管理写作稿件，但稿件仍是“文章草稿”，不是聊天对话。所有数据保存在 localStorage，切换存档时保留当前写作内容，不触发学习数据保存。

## 风险

- 写作存档引入新的 localStorage 数据模型，需要和现有 `linguatype.writingDraft.v1`、`linguatype.writingSetup.v1` 共存并迁移。
- 切换存档时如果自动保存当前稿，必须避免覆盖错误稿件或丢失正文。
- 抽屉式 Writing Setup 需要区分“设置草稿态”和“已保存 setup”，避免输入过程中触发大纲检查。
- Selection Actions 位置计算要覆盖多段 textarea、滚动容器和窗口边界，避免浮层越界或错位。
- 主界面向 AI 产品靠齐时要避免变成 chatbot/dashboard，仍需让正文编辑器保持第一优先级。
