# v0.3 文章地图

## 背景

LinguaType 已经具备当前句增强、段落健康、手动段落流畅度检查、写作存档、表达库和写作习惯等能力，但全文层面仍缺少一个低打扰的结构诊断入口。用户写出多段文章后，当前只能逐句或逐段处理问题，很难先看清全文主旨、段落角色、段落关系和优先修改顺序。

v0.3 的合理方向是新增“文章地图”：一个 Office 大纲式的一站式文章检查工作台。它借鉴会议 AI 总结把连续信息流整理为结构化资产的思路，也借鉴 Word 大纲折叠/展开让用户聚焦局部内容的心智，但迁移到 LinguaType 后必须保持 editor-first、local-first、用户确认后才修改的产品边界。

## 目标

- 新增“检查文章地图”入口。
- 新增 `POST /api/check-document-map`，通过 LLM provider service 生成全文结构地图。
- 将全文主旨、结构判断、全文问题、段落地图和优先修改建议呈现在可折叠大纲面板中。
- 保持正文为一个连续长文本输入面，不把正文拆成大纲卡片。
- 支持点击问题或段落节点定位并高亮正文中的对应段落。
- 在每个段落节点整合“查看建议”和“检查本段”入口。
- 新增 `linguatype.documentMapCache.v1`，按 archive、文本、setup 和 provider 上下文缓存文章地图。

## 非目标

- 不做全文流畅度改写。
- 不返回 `revisedDocument` 或全文改写文本。
- 不提供作文评分。
- 不自动实时检测全文。
- 不自动调整段落顺序。
- 不自动生成过渡句、续写段落或新的论点。
- 不触发 `/api/extract-learning`，不保存 Learning Library 或 Correction Events。
- 不新增登录、数据库、云同步、历史版本对比或复杂可视化图谱。

## 用户价值

文章地图让用户先看见文章结构，再决定处理哪一段。它承担诊断、定位和调度职责：全文层判断结构问题，段落节点呈现轻量健康摘要，用户再按需进入现有 Paragraph Flow 做当前段深检查，最终仍由用户手动决定是否 Apply 段落或当前句建议。

## 参考心智

- 飞书会议 AI 总结类产品把连续会议内容整理为摘要、章节、待办等结构化资产；文章地图对应把写作流整理为文章结构地图。
- Microsoft Word 的折叠/展开体验基于 outline level 和 heading，用户可以只聚焦某一标题下的内容；文章地图对应提供段落节点的折叠、展开、定位和聚焦。
