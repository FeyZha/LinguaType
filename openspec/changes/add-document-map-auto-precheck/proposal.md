# 变更提案：文章地图自动预检查

## 背景

v0.3 已经把文章地图作为全文结构检查入口。用户现在希望补充一定程度的自动逻辑：系统可以在写作过程中本地感知结构变化，并在低打扰条件满足时静默准备文章地图缓存，但不能自动弹出面板、不能自动改写正文，也不能自动进入段落流畅度检查。

## 目标

- 在前端本地判断文章地图是否为空、可检查、过期、需要检查、检查中、已有新结果或失败。
- 在用户停顿且文本变化足够时，后台预检查文章地图并更新 `linguatype.documentMapCache.v1`。
- 在文章地图入口旁显示轻量状态，例如“可检查”“整理中”“N 个发现”“可能已过期”。
- 在触发设置中新增“文章地图自动检查”模式。
- 保持所有深度动作由用户触发：打开文章地图、查看建议、检查本段、Apply 段落建议。

## 非目标

- 不做实时全文批改。
- 不自动展开文章地图。
- 不自动调用 `/api/check-paragraph-flow`。
- 不自动改写、排序、补写或生成段落。
- 不保存 Learning Library 或 Correction Events。
- 不增加登录、云同步或服务端持久化。
