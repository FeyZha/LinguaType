# v4 运行、汇总与复测

## 1. 三个检查点

| 检查点 | 来源 | 判断 |
|---|---|---|
| `one_call_generation` | 20 个原始 case | 一次响应是否覆盖全部顶层片段并生成完整内部支架包 |
| `progressive_reveal` | 复杂项的确定性投影 | 首屏不泄漏英文，点击只揭示对应英文且无模型调用 |
| `user_composition_boundary` | 全部支架包 | 多项可组合，但没有直接交付完整命题或整句 |

## 2. 调用口径

```text
20 个 case = 20 次模型调用
复杂项点击次数 = 0 次模型调用
取消、再次揭示、揭示多个 = 0 次模型调用
```

离线 runner 保存内部支架包。可见性验证通过纯函数投影或静态契约完成，不模拟第二次模型响应。

## 3. 报告顺序

1. 20 次模型调用的成功、失败与协议合规；
2. 实际 direct / scaffold-set 分布及与人工参考的差异；
3. 中文支架数量、中英配对完整性与首屏泄漏检查；
4. 四维逐 item / scaffold 分布；
5. 20 case 取最差结论；
6. 独立模型预审与用户人工覆盖；
7. 评分锁定后再合并分类切片字段。

四维分别报告 1 / 2 / 3 分布，不求总分：

```text
semantic_fidelity
scaffold_quality
assistance_calibration
user_composability
```

## 4. 版本边界

- v4 把两次生成改为一次生成加本地揭示，因此与 v3 不直接比较模型质量提升。
- v4 首次运行建立新 baseline。
- 后续只有相同 v4 eval set、rubric、Prompt、模型参数下的单变量修改才可直接比较。
- 离线结果不能证明用户会点击、如何组合、等待体验改善幅度或 IELTS 提分。
