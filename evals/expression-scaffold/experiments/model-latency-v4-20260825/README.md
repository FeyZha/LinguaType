# v4 国内模型响应速度筛选

## 目的

在不改变冻结 v4 输入、Prompt、schema 和输出校验的前提下，比较候选模型从请求发出到“完整合法支架可展示”的等待时间。

本轮只做内部模型筛选，不评价真实用户满意度，也不把公开榜单速度当作本产品实测结果。

## 首轮设计

- 模型：现有 LongCat-2.0；DeepSeek V4 Flash 非思考模式。
- case：`LT-ESC-001`、`LT-ESC-010`、`LT-ESC-019`（直接表达）；`LT-ESC-005`、`LT-ESC-015`、`LT-ESC-020`（复杂支架）。
- 重复：每个 case、每个模型 3 次；另做 1 次不计入统计的预热。
- 顺序：按 case 与轮次交错模型顺序，避免顺序性负载偏差。
- 并发：1；模拟当前单用户内部原型。
- 固定：A 输入（题目、完整全文、目标句）、v4 Prompt、v4 schema、温度 0、最大输出 4096、120 秒超时、无模型重试。

## 指标

主指标：

- 完整合法结果耗时 P50、P90。
- 完整结构与协议成功率。

解释指标：

- 平均耗时与范围。
- API 返回的输入、输出 token。
- 基于当前公开价格的单次调用成本估算。

## 边界

- 非流式结构化返回无法把 TTFT 转化为首屏模型内容，因此不把 TTFT 作为本轮主指标。
- 6 个 case × 3 次只能作为候选筛选，不能替代完整 20 case 回归。
- 输出语义只保留人工抽检入口；本轮智能能力不是主要排序项，但明显错误或不能完成结构协议会淘汰模型。
- 密钥和 endpoint 不写入运行产物；只保存 endpoint 的 SHA-256 指纹。
