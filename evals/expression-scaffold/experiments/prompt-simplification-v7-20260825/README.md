# v7 系统提示词精简对照

## 目的

在吸收用户对 v6 的粒度反馈后，判断更短的系统提示词能否降低输入成本和等待时间，同时不损害结构稳定性与产品边界。

## 两版共同的新规则

1. 复杂片段默认拆 2 个支架，只有 3 个独立实义单位时才拆 3 个，禁止 4 个。
2. 连接词、情态词、程度词、结构助词等附属成分不能独立成为支架，必须并入相邻实义支架。
3. 产品侧继续锁定 `itemId`、`sourceZh` 与 `requiredAction`，模型只生成英文表达或支架内容。
4. 非流式、单次调用、temperature 0、零自动重试。

## 唯一实验变量

- `full`：完整展开规则，并给出少量反例词。
- `compact`：删除重复解释和反例，只保留同义约束。

题目、全文、目标句、items_json、结构 schema、DeepSeek 模型参数与调用方式保持一致。两版按 case 交错执行，每版重复两轮，减少服务时段波动造成的偏差。

## 判断顺序

1. 硬门槛：协议成功、路由一致、复杂支架数不超过 3、无附属成分独立支架。
2. 效率：平均输入/输出 token、P50/P90 与平均完整返回时间。
3. 质量：并排材料由用户人工抽查；自动指标不能替代语义审核。

冻结 v4 case 与 canonical schema 不修改。本实验结果不能证明真实用户效果。
