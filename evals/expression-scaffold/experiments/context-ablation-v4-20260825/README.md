# v4 作文上下文量消融

状态：已关闭。A/B/C 已运行并完成隔离 Codex 盲审；用户确认沿用 A（完整全文），不再复测 B/C。运行结果只写入独立 `runs/<run_id>/`，v4 冻结文件未修改。

## 要回答的问题

这次只判断 `full_essay` 中额外作文语境的离线边际价值，不判断 `task_prompt` 或 `target_sentence` 是否必要。

| 条件 | `full_essay` 实际传入值 | 用途 |
|---|---|---|
| A | 完整全文 | 引用现有 v4 baseline |
| B | 前一句＋目标句＋后一句 | 观察更远前文是否提供额外价值 |
| C | 仅目标句 | 观察相邻句是否提供额外价值 |

三组保留完全相同的字段名、Prompt、schema、模型参数、case 与 rubric。C 仍把目标句放入 `full_essay` 槽，因此目标句与 A/B 一样出现两次；唯一变化是额外上下文量。

C 测试的是移除目标句周边作文信息，不测试删除 `full_essay` 字段本身。

## 执行边界

- B/C 使用独立 runner：`run_context_ablation_v4.py`。
- 每个 case 仍只调用模型一次，揭示调用为零。
- B 的窗口必须能从冻结全文确定性提取；任何目标句不唯一、不等于完整句、缺少前后句的情况都直接失败，不回退全文。
- 每次运行保存实际输入快照、模型结构化输出、首屏投影与调用指标。
- A 是历史运行，不是同期交错对照，因此首轮只能形成探索性结论。
- B 与 C 也分别运行，不是按 case 交错；两组差异仍可能混入服务端时序变化。
- A 未保存端点指纹，只能核对模型名、Prompt、schema、参数和冻结资产，无法证明 A/B/C 的服务端实例完全相同。
- 输出质量仍需独立 Codex 审核和用户校准；结构成功不能替代语义质量结论。
- 盲审统一提供 canonical 完整全文、`intent_zh` 与 `must_not_add`，但隐藏候选实际来自 A/B/C 的哪一种生成输入。
- 本轮只用于选择下一轮同期复测候选，不直接决定产品删除或保留字段。
- 历史 A 没有同口径的逐 case token 与模型调用耗时，首轮不能声称 A/B/C 的成本或等待改善。

## 样本覆盖偏差

冻结的 20 条样本全部把目标句放在全文倒数第二句。B 因而都等于全文最后三句。该设计可以检查较远前文是否有价值，但不能证明任意句子位置都能稳定使用同一窗口策略。
