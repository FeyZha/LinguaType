# DeepSeek v6 控制权外移定向实验

## 结论

v6 已验证“框架不变、控制边界改变”可以运行：9 个目标 case 的 `sourceZh` 和 `action` 均由产品侧生成并锁定，模型只填写英文或支架内容；9/9 最终通过冻结 v4 协议。用户随后完成会话式人工审核，结论为 7 pass、2 needs improvement、0 bad case；两个问题均为复杂支架拆出了低价值功能词。

每版每条只调用一次，样本量很小，延迟差异不能解释为稳定的速度变化。

## 控制权变化

| 字段或判断 | v5 | v6 |
| --- | --- | --- |
| 顶层中文片段 | 模型复制，本地校验 | 本地直接写入最终结果 |
| 帮助方式 | 模型选择，本地比较 | 本地规则确定并写入最终结果 |
| `itemId` | 无 | 本地创建，模型只能回传对应 ID |
| 英文表达 | 模型生成 | 模型生成 |
| 中文支架与隐藏英文 | 模型生成 | 模型生成 |
| 最终用户结构 | 模型结构直接校验 | 本地合并后再按冻结 v4 校验 |

## 临时路由规则边界

“10 个及以下中文字符直给、11 个及以上拆支架”在当前冻结 25 个片段上与人工定义 25/25 一致。这只是当前样本分布上的架构验证信号，不能证明规则适用于真实用户的长短语、简短完整命题或其他边界表达。

## 人工校准结果

- `LT-ESC-016`：把“可能”单独作为支架，不符合产品定位，应与“造成不便”等核心谓语合并。
- `LT-ESC-017`：第二个支架已经用 `while` 表达关系，又单独返回“同时”，重复且细碎。
- 其余 7 个 case 用户认为大体没有问题。

结构化人工结果见 `human-calibration-v6.jsonl` 与 `human-calibration-summary.json`。修复上述支架粒度规则前不运行完整 20 case，也不修改内部原型。

## 证据边界

本轮证明控制架构可运行，并在 9 个定向离线 case 上完成会话式人工校准。不能写成真实体验或任务成功率提升。
